# Artifacts Guide

## Overview

Artifacts are self-contained HTML or React/TSX components generated by AI and displayed inline in chat. Each artifact card shows a type badge (HTML or React/TSX), a title extracted from the source, and a row of action buttons.

## Artifact Cards

### HTML Artifacts

HTML artifacts are rendered in a sandboxed iframe with optional Alpine.js, HTMX, or Tailwind CSS runtimes. The card header shows the page `<title>` tag value (falling back to "HTML Artifacts"). The `HtmlArtifactsCard` component handles preview document assembly asynchronously via `loadArtifactSettings`.

### React/TSX Artifacts

React artifacts are transpiled in the main process via `window.api.artifacts.compileReact`. The card title is extracted from the default-exported component name. Compilation errors are shown inline as a styled error document in the popup.

## Action Buttons

Each non-streaming card shows the following actions:

| Button | Description |
|--------|-------------|
| Preview | Opens the full preview popup |
| Copy | Copies the raw source to clipboard |
| Open External | Writes the preview doc to a temp file and opens it in the system browser |
| Download | Saves the source file locally |
| Edit with AI | Opens the 3-pane iterative designer (see below) |

## Iterative AI Design

The **Edit with AI** button (wand icon) opens the `ArtifactDesigner` — a 3-pane interface for iteratively improving an artifact through conversation with the AI model.

### Opening the Designer

Click **Edit with AI** on any artifact card that has content. The button is disabled while the card has no source. The designer opens pre-loaded with the card's current source.

### Using the Designer

The designer has three panes:

- **Chat pane** (left): Conversation transcript and prompt input. Type a description of what you want to change and press **Send** or `Ctrl+Enter` / `Cmd+Enter`.
- **Code pane** (center): Read-only view of the current generated source. Updates after each successful design turn.
- **Preview pane** (right): Live preview of the artifact. For HTML artifacts the preview updates synchronously. For React artifacts the preview is compiled asynchronously after each build.

### Design Turn Lifecycle

1. Enter your prompt and send.
2. The model streams the updated source. The chat pane shows status messages.
3. For React artifacts, the main process compiles the TSX output. For HTML, the document is assembled directly.
4. If the build succeeds, the preview pane shows the rendered artifact (`phase = preview`).
5. If the build fails, diagnostics appear in the chat pane and a **Fix it** button is shown (`phase = repair`). Click **Fix it** to auto-compose a repair request, or type a manual correction.

### Saving to Library

When the designer reaches `phase = preview`, a **Save to Library** button appears. Clicking it persists the current source as an `ArtifactRecord` via `useArtifactLibrary().saveArtifact`. A confirmation message appears in the chat pane on success.

### Preview Architecture

**Decision — async preview builder**: `ArtifactDesigner.buildPreviewDocument` accepts `(source: string) => string | Promise<string>`. The designer resolves the result via `useEffect`, allowing HTML cards to pass a sync-wrapped async settings loader and React cards to pass a fully async compile pipeline. This avoids a "placeholder only" approach and shows real compiled output in the preview pane.

## Library

Saved artifacts appear in **Settings → Artifacts → Library**. From there you can rename, fork, delete, or re-open artifacts. The library uses the same `useArtifactLibrary` hook wired in the designer's `saveArtifact` prop.

## i18n Keys

All user-visible strings in artifact components use `i18next`. Relevant key namespaces:

- `settings.artifacts.designer.*` — designer pane labels, buttons, status messages
- `chat.artifacts.button.*` — card action button labels
- `settings.artifacts.library.*` — library page labels
- `html_artifacts.*` — HTML card streaming state labels
